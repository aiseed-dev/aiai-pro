# 民泊の受付(受付端末と経営者の画面)

あなたは、この会社が、民泊の受付を自分のアプリで動かすのを手伝います。専門の言葉は、初めて出るときに
1 度説明してください。法律の助言はしません。条文と官庁の文書に書いてあることを示し、決めるのは会社です。

[honnin](../honnin/)(本人確認と名簿)、[kagi](../kagi/)(鍵)、[tsuuchi](../tsuuchi/)(通知)を 1 つの流れに
つなげた形を書いています。ここに書くのは、1 つの住宅を 1 つのプロセスで動かす小さな形です。部屋が
いくつもある宿や、複数の住宅は、会社が決めてから広げます。

## 守ること

- 宿泊者の名前、住所、旅券番号、顔と身分証の写真を、AI への依頼に貼りません。あなたも、台帳と画像の
  置き場を読みません。設計と試験は、項目の名前と、架空の名前、バイト列の代わりの値でできます
- 経営者の合言葉、錠のメーカーの API の鍵と機器の秘密の鍵は、会社の人が環境変数に入れます。会話にも
  リポジトリにも入れません。入れてしまったら、まず無効にして作り直します
- 台帳は追記だけにします。訂正は新しい記録として書きます。鍵の失効も、鍵を消すのではなく、失効の
  記録を足します
- 台帳に書く前に、入力を検査します。誤った入力を台帳に残しません。残ると、消せないからです
- 画像(顔と身分証)は、台帳の本体に入れず、内容のハッシュを名前にして別に置きます。台帳にはハッシュ
  だけを書きます。名簿と画像の保存の期間は [honnin](../honnin/) の通りで、期間が過ぎたら消す仕事を会社が
  決めます。追記だけの台帳と消す義務をどう両立させるかは、会社が決めて書いておきます
- 受付端末は届出住宅の中に置きます。本人確認が「住宅やその近くから送られている」と確かめられる
  からです。端末の名前を決めておき、台帳には「受付端末:名前」を位置として書きます
- 顔の照合を入れるまでは、どのチェックインも「保留」にして、経営者が写真を見て決めます。照合の
  結果が承認にも拒否にも届かない値のときも、保留に回します
- 経営者の画面は、家の中のネットワークか、手元から開く形にします。既定の待ち受けは 127.0.0.1 です。
  合言葉だけの入口なので、インターネットに出すときは [ninshou](../ninshou/) のサインインに替えます

## 流れ

1. 経営者が予約を入れます。氏名、到着、出発(年-月-日 時:分)、連絡先を書き、6 桁の受付番号が
   出ます。番号は乱数で、まだ有効な予約と重ならないようにします。出発が到着より前なら、台帳に
   書かずに断ります。番号を宿泊者に送るのは経営者です([tsuuchi](../tsuuchi/))
2. 宿泊者が、受付端末で番号を入れます。結果は次の語のどれかになります

   | 語 | 意味 | 次 |
   |---|---|---|
   | 番号違い | 番号がない、または出発を過ぎた | 最初の画面に戻し、入れ直してもらう |
   | 期間外 | 到着日より前 | 到着日になってから使うよう伝える |
   | 要記入 | 初めて | 名簿と写真の画面へ |
   | 保留 | 記入が済み、経営者の判定を待っている | 待つ画面へ |
   | 承認 / おかえり | 確認済み。有効な鍵がある | 鍵を開ける |
   | 拒否 | 確認できなかった、または有効な鍵がない | 連絡先を出す |
   | 入力不足 | 名簿の必須の項目が空 | 足りない項目を示して記入の画面に戻す |

3. 名簿を書き、顔と身分証をその端末で撮ります。名簿の項目は、住所、職業、国籍、旅券番号です。氏名と
   到着日、出発日は予約から入れます。日本に住所のない外国人(国籍が日本以外)は旅券番号を必須に
   します([honnin](../honnin/))。名簿の様式で検査し、通ったら、本人確認の記録を台帳に書きます。
   名簿の下書きは台帳の外に置きます。下書きを正式な名簿にするのは、承認のときです
4. 宿泊者は待つ画面で待ちます。端末は 2 秒おきに状態を見ます。最長 20 分で止めます。承認か拒否に
   なったら結果を出し、20 秒たつと最初の画面に戻します。戻すときは、前の人の入力を消します
5. 経営者が「保留」の一覧を開き、顔、身分証、名簿の下書き、判定の理由を見て、承認か拒否を押します。
   判定は、経営者の名前で台帳に書きます
   * 承認: 名簿を台帳に書き(本人確認の番号を付けます)、下書きを消し、鍵を出して開けます。鍵の開始は、
     到着の時刻と今の早いほうです。早く着いた人には、今から使える鍵が出ます。終了は出発の時刻です
   * 拒否: 鍵も名簿も残しません。下書きを消します
6. 滞在中は、同じ受付番号で開きます。確認が承認で、有効な鍵があるときだけ開けます。出発の時刻で鍵が
   切れます。早く止めたいときは、経営者が鍵を失効させます
7. 偶数月の 15 日までに、定期報告を出します(次の節)

## 経営者の画面

合言葉で開きます。比べるときは、時間で差が出ない比べ方にします。合言葉を環境変数に入れていないときは、
起動のたびに作って、標準エラーに 1 度だけ出します。5 つの区画があります。

| 区画 | 見せる物 |
|---|---|
| 保留 | 顔、身分証、名簿の下書き、受付番号、判定の理由、承認と拒否。件数を印にする |
| 今日 | 今日の到着、滞在中、出発。氏名、到着、出発、受付番号 |
| 予約 | 予約を入れ、受付番号を大きく出す |
| 鍵 | 有効な鍵(氏名、錠、開始、終了)と失効 |
| 記録 | 台帳の検査(記録のつながりが正常かと枚数)と、次の定期報告 |

## 定期報告

住宅宿泊事業者は、届出住宅ごとに、毎年 2 月、4 月、6 月、8 月、10 月、12 月の 15 日までに、それぞれの月の
前の 2 か月について、次の 4 つを都道府県知事に報告します(法第 14 条、施行規則第 12 条。2026-10-10 に
e-Gov の条文で確かめました)。

1. 届出住宅に人を宿泊させた日数
2. 宿泊者数
3. 延べ宿泊者数
4. 国籍別の宿泊者数の内訳

アプリは、台帳の予約と名簿から、この 4 つを数えて、報告に写せる形で出します。次の報告の期間と期限は、
今日の日付から決めます。

| 今日 | 対象の期間 | 期限 |
|---|---|---|
| 2026-10-01(偶数月の 15 日まで) | 2026-08-01 〜 2026-09-30 | 2026-10-15 |
| 2026-10-20 | 2026-10-01 〜 2026-11-30 | 2026-12-15 |
| 2026-12-16 | 2026-12-01 〜 2027-01-31 | 2027-02-15 |
| 2027-01-10 | 2026-12-01 〜 2027-01-31 | 2027-02-15 |

偶数月の 15 日までは、その月の期限の報告を、それより後と奇数月は、次の偶数月の報告を指します。
年をまたぐ月(12 月と 1 月)の試験を必ず書きます。報告の出し方(民泊制度運営システム)は、会社の人が
確かめます。アプリは数えるところまでです。

## つなぐ物

- 台帳、名簿の様式、本人確認、鍵、定期報告の数え方は、画面と切り離した部品(1 つの `Home` のような
  クラス)にまとめます。画面は、部品を呼んで表示するだけにします。試験は部品に書きます
- 鍵は、錠のドライバを差し替えられる口にします。試験では、開けた回数を数えるだけの疑似の錠を
  使います。実機の錠は [kagi](../kagi/) の選び方で決めます。実機の鍵は手元だけに置きます
- 顔の照合は、差し替えられる口にします。口の中身がないあいだは、別々の写真を、承認にも拒否にも
  届かない値と見なして保留にします
- 文言は日本語と英語を持ち、画面の右上で切り替えます。宿泊者に出す言葉は、法律の言葉をそのまま出さず、
  「番号」「名簿」「写真」「確認」のように短くします。確認できなかったときは、お電話くださいと連絡先を
  出します
- 設定は環境変数で渡します。記録の置き場、家の名前、経営者の合言葉、受付端末に出す連絡先、錠の指定
  (疑似、または機器の種類と引数)、待ち受けの場所と番号です

## 画面を Flet で作るとき

- イベントの手には `async def` を渡します。`lambda` でコルーチンを返しても動きません
- 受付端末と経営者の画面は、1 つのプロセスで、経路(`/` と `/owner`)で切り替えます。経路が変わる
  ときの画面は `on_route_change` で作り直します。住所を変えても同じ接続が続くからです
- 色や角の丸みは画面の中に直に書かず、見た目の部品(見出し、本文、カード、ピル、鍵盤、段の印など)
  に集めます
- 画面を確かめるときは、Flet の Web の文字がアクセシビリティの木に出ないので、先に `flt-semantics-placeholder`
  を押してから木を読みます。文字の入力は、`flt-text-editing-host` の `input` に値を入れ、`input` と
  Enter を送ります。経営者の左の案内は、画面を出すたびに作り直されて参照が古くなるので、押すときは
  座標を使います
- 起動を確かめたあとは、使ったポートを空けます

## 確かめること

部品の試験に、次を入れます。名前は架空、写真はバイト列の代わりの値にします。

- 予約で 6 桁の番号が出る。出発が到着より前なら断り、台帳に何も増えない
- 間違った番号、到着日より前、出発のあとの番号が、それぞれ番号違いか期間外になる
- チェックインは保留になる。位置に受付端末の名前が書かれ、顔と身分証のハッシュが記録される。保留の
  一覧に名簿の下書きが出て、写真が取り出せる
- 承認すると、名簿が台帳に入り(本人確認の番号つき)、鍵が出て、錠が 1 回開き、保留の一覧から消える。
  滞在中に同じ番号を入れると「おかえり」になり、もう 1 回開く。台帳のつながりの検査が正常
- 早く着いた人の鍵の開始が、その時刻になる
- 拒否すると、鍵も名簿も下書きも残らない
- 住所や旅券番号が空のとき(日本以外の国籍)は「入力不足」で、台帳に何も増えない。国籍が日本なら
  旅券番号が空でも保留になる
- 今日の一覧(到着、滞在中、出発)が正しい。失効すると有効な鍵の一覧から消える。報告に、日数と国籍別の
  人数が出る
- 定期報告の期間と期限が、上の表の日付(年またぎを含む)で合う

実機の錠、顔の照合、サーバーに置いての運用は、まだ確かめていません。動かした人の報告で直します。
