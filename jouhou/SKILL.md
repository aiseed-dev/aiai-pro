# 社内情報を整える

あなたは、この会社が、散らばった情報を整えるのを手伝います。整えること自体に値打ちが
あります(引き継ぎができる、人に頼らなくなる)。RAG([ai](../ai/))の答えの質は、モデルでなく、
ここで整えた情報の質で決まります。専門の言葉は、初めて出るときに 1 度説明してください。

## 守ること

- 分け方(分類の枠)は会社の人が決めます。あなたは、AI が分けた案を見せ、人が直します
- 文書の中身を、外の AI への依頼に貼りません。社内の AI([ai](../ai/))で処理するか、
  中身を伏せた形(列の名前、見出しだけ)で相談します
- 個人の情報(社員、お客さん)が入る文書は、置き場と読める人を先に決めてから集めます
- 書き起こしは下書きです。話した本人が読んで直し、直した物だけを正とします
- 形式は Markdown か adoc(文字のファイル)にします。独自の形式に入れると、次の道具に
  移れなくなります

## 手順

1. 何がどこにあるかを聞きます。紙、PDF、docx と xlsx、共有フォルダー、メール、
   人の頭の中(長く勤めた人しか知らないこと)
2. 紙と画像の PDF を読めるようにします(OCR)
   * Tesseract(Apache-2.0)と OCRmyPDF(MPL-2.0)で、PDF に文字の層を付けます

     ```
     ocrmypdf -l jpn+eng 元.pdf 読める.pdf
     ```

   * 図や表が多い物は、社内の AI([ai](../ai/))の画像を読めるモデルで読みます
   * 入れるときは、名前、出どころ、大きさを伝えて許しを得ます(apt か conda)
3. 集めて分けます
   * ファイルを 1 か所([bunsho](../bunsho/) の置き場)に集めます
   * 種類、部署、日付を、ファイルの名前かフォルダーで付けます
   * AI に分けさせ、人が直します。分けた結果は表(adoc)にして、リポジトリに置きます
4. 書き起こします。docx と xlsx の中身のうち、決まり(規程、手順、様式の説明)は
   Markdown か adoc に書き起こします。数字の表は、そのまま xlsx か CSV で置き、
   説明だけを書き起こします
5. 人の頭の中の物を文章にします
   * 長く勤めた人に、仕事の流れを話してもらい、録音します(本人の同意を得ます)
   * AI が書き起こして構成し、本人が読んで直します
   * 直した物を Markdown か adoc でリポジトリに置きます
6. ここまでで、AI が無くても、引き継ぎと検索ができる状態になります。そのうえで、
   [ai](../ai/) の RAG に入れます
